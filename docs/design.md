# 하늘섬 연대기 — 2인 장기 운영 웹 MMO 기획

## 현실 체크
원하는 조합은 크게, 작업 시간(둘이 합쳐 주 5시간 이하)은 작다. 그래서 아주 작게 시작해 업데이트마다 하나씩 붙이는 구조로 간다.

- 원하는 것: 3D, 웹 MMO, 실시간 액션, 성장·수집·PvP·하우징·레이드, PC·아이패드·폰 전부
- 전부 한 번에 하면 상업 스튜디오 몇 년 분량이라 중간에 멈출 가능성이 높다
- 장기 운영형이 목표라서 작게 시작하는 방식이 오히려 맞다

## 아이디어: 하늘섬 연대기
하늘에 떠 있는 섬을 하나씩 열며 같이 사냥하고 성장하는 로우폴리 판타지 웹 MMO다. 플레이어마다 자기 섬을 하나씩 가진다.

### 섬 = 업데이트 단위
| 확장 요소 | 섬으로 풀기 |
|---|---|
| 새 지역 | 새 섬 1개 (테마·몬스터·보스 세트) |
| 시즌제 | 시즌마다 "이번 시즌 섬" 오픈, 랭킹은 시즌 단위 초기화 |
| 레이드 | 섬 끝의 보스 섬 |
| 하우징 | 개인 섬 꾸미기 |
| 수집 | 섬마다 나오는 펫·도감 |
| PvP | 나중에 아레나 섬으로 따로 추가 |

### 핵심 플레이
1. 허브 마을
2. 사냥 섬
3. 보스
4. 장비 획득
5. 다음 섬 해금

조작은 실시간 액션이고, 카메라는 쿨터뷰와 3인칭을 전환할 수 있다.

## 추천 기술
3D는 Three.js, 서버는 Supabase, 에셋은 무료 로우폴리로 간다.

| 항목 | 추천 | 이유 |
|---|---|---|
| 3D | Three.js | 자료·예제가 가장 많아 Claude가 잘 다룬다. 아이패드 사파리에서도 돌아간다 |
| 서버 | Supabase | 로그인, DB(캐릭터 저장), Realtime으로 위치 동기화까지 처리 |
| 에셋 | Kenney, Quaternius 로우폴리 | 무료, 스타일 통일이 쉽고 폰에서도 가볍다 |

**주의:** Supabase Realtime은 지인 10~20명이 서로 보이는 수준이면 충분하다. 다만 서버가 판정하는 구조가 아니라 전투 판정을 각자 브라우저에서 한다. 가족·친구끼리면 문제없지만, 공개 후 PvP 랭킹이 중요해지면 서버 구조를 바꿔야 한다.

## 2인 역할 분담
코드(시스템)와 데이터(콘텐츠)로 나눠서 둘이 같은 파일을 건드리지 않게 한다. 둘 다 Claude Code를 쓰는 기준이다.

| 담당 | 맡는 것 |
|---|---|
| A: 엔진·시스템 | 캐릭터 조작, 카메라, 전투 판정, 멀티플레이 동기화, 저장 |
| B: 콘텐츠·UI | 몬스터, 아이템, 스킬, 퀘스트, 섬 데이터, 인벤토리·HUD 화면 |

### 협업 규칙
- 콘텐츠는 전부 JSON 데이터로 뺀다. B가 몬스터나 섬을 추가해도 A의 코드를 안 건드려 충돌이 거의 없다
- 깃허브: 기능마다 브랜치를 따서 PR로 합친다
- 둘 다 같은 `CLAUDE.md`(폴더 구조, 코드 규칙, 데이터 형식)를 써서 Claude 두 개가 다른 스타일로 짜는 것을 막는다
